        Both Qwen selectors improved document recall, but 0.6B did not improve the mean judge score. Qwen-4B had the highest observed score; its paired interval versus Dense5 includes zero, so an answer-quality improvement is not confirmed.

        Separate end-to-end test · 10 audio queries

        Audio to complete answer: ≈9 s with Dense5 vs ≈17 s with Qwen-4B.

        Most of the extra time came from reranking. The evidence is clearer for higher recall and higher latency than for better answers.

        Document chunking: getting the key sentence

        Recorded offline experiment · not a live feature

        What are the steps involved in purchasing a residential property?

        Document rank
        8
        Chunk-based rank
        3
        Start building a down payment and emergency fund. Pay down consumer debt/student loans.

        Source r_623105da59cf298f · Query q_d1397ae30111620c · Record: rag/experiments/DOCUMENT_CHUNKING_768.md

        Across 24 Practice questions with a 768-token input cap, chunking the same five documents did not improve the mean score when labelled evidence was already in the prompt. In the other group, ranking by chunks brought labelled text into the prompt for 3 of 12 questions.

        Here, the chunk-ranked prompt included these lines, and the answer mentioned all three recommendations. That shows evidence recovery in this example, not a general answer-quality gain.

        ASR: passing tests does not mean faster inference

        Recorded benchmark · one clip

        4/4 test suites passed. The four custom CUDA kernel groups reproduced the reference transcription.

        PyTorch
        521 ms
        All CUDA
        1,986 ms

        On this clip, enabling all custom kernels took 3.8× as long as PyTorch. Linear operations accounted for about 84% of all-CUDA kernel time.

        Takeaway: A better component metric does not guarantee a better system. Measure both the answer the user gets and the time it takes to get there.
