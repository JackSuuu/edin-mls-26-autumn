=== PDF PAGE 18 ===
What does one LLM call receive? 
Call 1 input:   Our knowledge base lives at kb.x.test.
Call 2 input:   Where does our knowledge base live? 
Call 2 is a separate request. Its input does not contain the address; so can’t answer.
abstract view of LLM call:   x t   ∼   p θ   (   · |   x 1 , . . . , x t − 1 ) . 
•   x 1 , . . . , x t − 1 : the tokens of this call’s input. We call them the   context . 
•   θ : the model parameters (fixed during inference).
Call 2 can use the address only if the runtime stores it and supplies it again.

An example agent: web page crawl assistant 
A page crawl example: a user asks an assistant to ingest the crawled web page x.test/1042
into a shared knowledge base. The knowledge base should not store a page twice, even
when the two copies differ a little. Such copies are   near-duplicates .
Arrangement   On the web page x.test/1042   Next step set by
One model call   Summarise this page   Application code
Tool calling   Emit   ingest_page("x.test/1042")   Model output; code runs it
Fixed workflow   Fetch, embed, search, insert if new   Application code
Agent loop   Read the tool result, emit the next call   Model output, each step 
•   A   tool call   is structured text in model output; runtime checks it and runs the function. 
•   An   agent   in this lecture is a loop of model calls and tool results. 
interpretation taken from ”Building effective agents” (2024), by Anthropic

ingest_page   tool call 
def ingest_page(page):
cands = memory.read_vector(query=page.emb, top_k=k)   # 1. search
match = verify_near_duplicate(page, cands)
if match is None:   # 2. new page
record = process_page(page)
memory.insert_page(record)
memory.insert_vector(page_id=record.id, emb=page.emb)
return {"action": "page_inserted", "page_id": record.id}
memory.upsert_alias(url=page.url, page_id=match.id)   # 3. alias
return {"action": "alias_updated", "match": match.id} 
insert   page   only when the search finds no near-duplicate

=== PDF PAGE 38 ===
The no-duplicate memory rule 
the memory (store) never holds two pages that are near-duplicates of each other.
Let   P   be the set of stored pages,   E   the encoder,   d   the distance and   τ   the threshold. 
I ( P   )   ≡ ¬∃   a, b   ∈   P   :   a ̸   =   b   ∧   d ( E ( a ) , E ( b ))   ≤   τ. 
•   Our toy case:   d   is the absolute difference and   τ   = 0 . 10 
•   In database terms such a rule is an   invariant :   P   is consistent if   I ( P   )   holds 
•   a commit (consistent write) that changes   P   into   P   ′ : if   I ( P   )   holds, then   I ( P   ′ )   must hold

=== PDF PAGE 43 ===
Learning from the past (DBMS): transactions and ACID 
Property   A transaction guarantees   In our   ingest 
Atomicity   All of its writes happen, or none   Page row plus vector
Consistency   Each commit keeps the declared rules   No pair within   τ 
Isolation   Concurrent ones do not interfere   A and B in Case 1
Durability   Committed data survives a crash   p stays stored 
•   In Case 1 each transaction alone kept the rule. Their interleaving broke it. 
•   So Case 1 is a failure of   isolation .

=== PDF PAGE 44 ===
Learning from the past (DBMS): isolation levels 
Assume pages and vectors live in one PostgreSQL database. Replay Case 1 at each level:
Level   A transaction reads   Case 1 result
Read Committed   Commits before each statement   p and q stored (inconsistent)
Repeatable Read   One snapshot per transaction   p and q stored (inconsistent)
Serializable   As if run one at a time   One aborts, then retries
retry runs after the other commit; its search finds the stored page and adds an alias

=== PDF PAGE 45 ===
Connecting the dots: one transaction or three? 
In one transaction 
BEGIN
R_V: search
W_R: insert page
W_V: insert vector
COMMIT 
Separated transactions 
BEGIN; R_V: search; COMMIT
BEGIN; W_R: insert page; COMMIT
BEGIN; W_V: insert vector; COMMIT 
•   In one: both stores are in one database, such as PostgreSQL with pgvector. 
•   Separated: lines 1 and 3 run in the vector store, line 2 in the relational store.
An isolation level protects only what runs inside one transaction.
